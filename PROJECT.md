# Concept project: Kinara Family Clinic (booking web app)

- **Type:** Concept project (our own showcase, built like a client product)
- **Owner:** Jitender (PrimeCraft Labs)
- **Status:** DONE / closed 2026-10-27 - live with v1 (booking app), v2 (doctor accounts), v3 (real-clinic essentials).
- **Showable:** yes (label it "Concept project", never a real clinic)
- **Stack:** Next.js 16 static export + Tailwind 4 + TypeScript; Firebase free Spark plan (Firestore + Auth);
  DiceBear "Notionists" avatars (CC0); Unsplash photos; Formspree email alerts. **₹0.**
- **Live link:** https://primecraftlabs.github.io/kinara-family-clinic/ (GitHub repo `kinara-family-clinic`;
  local folder keeps `demo-clinic`)

## What it does
- **Patients:** home (photos, services, story, how booking works, gallery, doctors, FAQ, visit), doctors page,
  live booking: published doctors only, working days minus leave days, free slots live, double booking impossible,
  booking code + Google Calendar / .ics + WhatsApp message; email alert to the clinic.
- **Clinic admin** (`/dashboard/`, staff role `owner`): all appointments live (filter, complete, cancel = frees slot,
  30-day auto-delete) and a Doctors tab: add doctor (hidden), edit profile + schedule + publish/hide, invite a
  doctor's login (Firebase emails them a "set your password" link), remove access, "Add the starter doctors".
- **Doctors** (staff role `doctor`): their own appointments only; their profile, avatar and leave days
  (schedule and publishing stay with the admin).
- **Front desk (v3):** add phone / walk-in bookings (same no-double-booking slots); Check in -> the day's token per
  doctor (transaction, `queues/{doctor_date}`), Today sorted by token; No-show; one-tap WhatsApp reminder link to
  the patient (free, staff press Send); clinic-wide holidays in a Clinic settings tab (`settings/clinic`, enforced
  by the rules); `/privacy/` notice + required consent stored on every booking (India DPDP Act).
- **Preview for visitors:** `/dashboard/?preview` (`&tab=doctors`) = admin view with sample data, nothing saved.
- Honest concept labelling: footer line, booking notice, WhatsApp prefix (`concept` in `src/config/clinic.ts`), noindex.

## Architecture (change one place; loose coupling)
```
src/config/    clinic.ts (details, rules, texts, notifications), firebase.ts (keys from env, db name, collections),
               avatars.ts, studio.ts, photos.json/.ts, brand.json (generated by jk/brand/sync.py)
src/data/      starter doctors (imported once by the admin), sample patients (preview)
src/lib/       pure logic, unit-tested: booking.ts (slots, leave, validation), doctors.ts (profile rules, ids),
               records.ts (exact Firestore shapes), calendar.ts, messages.ts
src/services/  types.ts = interfaces (BookingStore, DoctorStore, StaffAuth, TeamAdmin, Notifier)
               firebase/* and sample/* adapters + formspree-notifier; index.ts = the ONLY place choosing adapters
src/components UI only, talks to the interfaces (never imports Firebase)
src/app/       routes: / doctors/ book/ dashboard/ credits/ + not-found
firestore.rules  security (tested in tests/rules.test.ts)
```
Swap Firebase for another backend = new adapters + `src/services/index.ts`; screens don't change.

## Firebase (project `primecraft-concepts`, Firestore database named `default`, asia-south2)
- `staff/{uid}` role `owner` (added by hand in the console) or `doctor` + `doctorId` (added from the dashboard).
- `doctors/{id}` public only when `active`; `slots/{doctor_date_time}` public, no personal data;
  `bookings/{id}` admin sees all, a doctor only theirs. Leave days and hidden doctors are refused by the rules too.
- Web keys in git-ignored `.env.local` (NEXT_PUBLIC_FIREBASE_API_KEY / AUTH_DOMAIN / PROJECT_ID / APP_ID).
  CI needs the same four as **GitHub Actions variables** (repo Settings -> Secrets and variables -> Actions -> Variables).
- Deploy rules (owner logged in once with `npx firebase login` in a normal terminal):
  `npx firebase deploy --only firestore --project primecraft-concepts`
- Authentication -> Settings -> Authorized domains must include `primecraftlabs.github.io`.

## Turning it into a real client clinic
New Firebase project for the client; their details in `src/config/clinic.ts` (`whatsappUrl`, `concept` texts -> "",
`notifications.endpoint` -> their form), their photos in `photos.plan.json`, remove `robots: noindex`, add their
owner to `staff` in the console, import or add their doctors from the dashboard.

## Not built (ideas if a real clinic asks)

+ a server, i.e. Blaze); multi-clinic SaaS. Best next step is a pilot with one real local clinic.
